# App Canvas product boundaries

App Canvas is an MIT development tool operated with a coding agent. Launch
consistency with another product means comparable supported surfaces, not
identical SaaS capabilities or a claim that every feature is interchangeable.

| Surface | App Canvas contract |
| --- | --- |
| Distribution | Versioned GitHub source and checksummed package, CLI, agent guide, Codex/Claude skill install and standalone Claude marketplace. No unpublished npm registry claim. |
| Viewer and language | Original-code web previews, native overview adapter, checked flows, retained drafts, configurable panels; English default and the same eleven languages as launch material. |
| Product materials | Localized product page, repo walkthrough and release story, real synthetic-demo screenshots, TL;DR, versioned install commands, canonical/hreflang and agent-readable guides. |
| Usage measurement | Minimal allowlisted events, explicit source/surface separation, opt-out and self-host controls. A working collector and observed ingestion are separate release requirements. Anonymous installation IDs are not people or successful integrations. |
| Hosted interest | Cloudflare Workers + dedicated D1 waitlist, consent, removal code, rate/cap controls and retention. It is an interest test, not a hosted workspace. |

The OSS runtime has no customer billing, cloud account system, repository
upload/sync, private team workspace or cloud sharing service. The waitlist does
not provide those capabilities. Do not describe it as 100% SaaS parity with
Claude View or SosoAPI. No adoption, demand or waitlist numbers are invented.

For support, open a [GitHub issue](https://github.com/tombelieber/app-canvas/issues)
with a minimal synthetic reproduction and the tool/browser version. Never post
real app data, private source, health images, credentials or raw device traces.
